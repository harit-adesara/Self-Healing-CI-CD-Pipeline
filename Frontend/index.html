● After every failed run

Three ways it can end

Every failure gets triaged. What happens next depends on what actually broke.

AUTO-FIXED

A fix branch appears

The problem was something in your code, config, or dependencies. A new AI_FIX-<hash> branch is pushed with the patch and a clear commit message. Open a PR from it when you're ready to review.

NEEDS YOU

You get a suggestion, not a commit

Some failures — missing secrets, expired credentials, permission errors, upstream outages — can't be fixed by editing files. No code is changed; you get a plain-language explanation of what to do instead.

UNCLEAR

Nothing is touched

If there isn't enough signal to safely classify or fix the failure, it's left alone rather than guessed at. You'll see what was found so you can take it from there.

● Takes about two minutes

Connect your repository

The service is already running on our end. All you need to do is point your repo at it.

01

Install the GitHub App on your repo

It only asks for what it needs to read failures and push a fix branch — nothing more:

Contents: Read & write Actions: Read Metadata: Read
02

Add the webhook to your repo

In your repository, go to Settings → Webhooks → Add webhook and fill in:

https://self-healing-ci-cd-pipeline-1.onrender.com/webhook
Content type: application/json Events: workflow_run Events: push
03

Save, and keep working like normal

That's it. Nothing to install locally, nothing to configure in your workflow files. Next time a run fails, you'll see it show up as a new branch — or a note telling you what to do — without lifting a finger.

● Before you rely on it

Good to know

  • Fixes never land on your source branch directly — every change goes to its own AI_FIX-* branch first.
  • Treat that branch as a draft PR. Review it like you would any teammate's change before merging.
  • If a workflow re-runs on an existing fix branch, it's reused rather than creating a duplicate.
  • Superseded or stale workflow runs are automatically skipped, so you won't get fixes for a failure that's already gone.
  • Nothing is changed for issues it can't safely diagnose — you'll get a note instead of a guess.
  • Works alongside your existing CI setup. No changes to your workflow files are required to turn it on.
